# Getting Support

Thanks for your interest in WMOOP! Here is where to go, depending on what you need.

| I want to… | Go to |
|------------|-------|
| Understand the project | The [README](README.md) and the [whitepaper](docs/whitepaper.md) |
| Ask a question / discuss an idea | **GitHub Discussions** on the relevant repo |
| Report a bug in the model or tooling | Open an **issue** with the right template (see below) |
| Propose a new concept, domain, or cross-domain role | Open an **issue** using the matching template, then read [CONTRIBUTING.md](CONTRIBUTING.md) |
| Contribute as an AI agent | [AI_CONTRIBUTING.md](AI_CONTRIBUTING.md) |
| Report a security/supply-chain problem | [SECURITY.md](SECURITY.md) (do **not** open a public issue) |
| Raise an ethics or neutrality concern | [ETHICS.md](ETHICS.md) |
| Teach with WMOOP | The [academic program](docs/04-academic.md) |

## Issue templates

- **New concept** — add a class/property to an existing domain.
- **New domain** — propose a whole new domain or sub-domain.
- **Model bug / correction** — a fact is wrong, unsourced, or mis-modelled.

## Response expectations

WMOOP is a volunteer, community-run project. Maintainers triage issues and pull requests on a
best-effort basis. Clear, small, well-sourced contributions (see the Definition of Done in
[CONTRIBUTING.md](CONTRIBUTING.md)) are reviewed fastest.

## Community standards

All interactions are governed by our [Code of Conduct](CODE_OF_CONDUCT.md).
